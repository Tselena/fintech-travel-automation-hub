# 🏦✈️ Fintech & Travel Booking Automation Hub

Репозиторий содержит комплексный фреймворк автоматизации тестирования, объединяющий два независимых контура: **Финтех-модуль (API-тесты)** на базе локальной микросервисной архитектуры и **Тревел-модуль (кроссбраузерные UI/Mock тесты)** для внешнего контура.

Фреймворк разработан на стеке **Playwright + TypeScript** и полностью оптимизирован для стабильного запуска внутри сред без графического интерфейса, включая **WSL (Windows Subsystem for Linux)** и контейнеры **CI/CD**.

---

## 🏗️ Архитектура и структура проекта

Проект разделен на логические слои для обеспечения изоляции данных, масштабируемости и простоты поддержки:

```text
├── .github/workflows/       # Конфигурация CI/CD пайплайна (GitHub Actions)
├── fixtures/                # Кастомные фикстуры страниц и статические данные
│   ├── page-fixture.ts      # Сетевой фильтр UI (блокировка Flocktory, картинок, аналитики)
│   └── mock-hotels.ts       # Заглушка (Stub) ответа API автокомплита городов
├── pages/                   # Классы страниц (Page Object Model)
│   └── MainPage.ts          # Бизнес-логика главной страницы агрегатора отелей
├── tests/                   # Папки с тестовыми спецификациями
│   ├── api/                 # Контур API: Тестирование идемпотентности финтех-модуля
│   └── ui/                  # Контур UI: Сценарии поиска отелей (Чистый UI + Mock API) тревел-модуля
├── server.ts                # Локальный мок-сервер на Express для API-тестирования
├── middleware.js            # Перехватчик запросов для симуляции идемпотентности платежей
├── db.json                  # Файловая БД транзакций (очищается перед каждым тестом)
├── tsconfig.json            # Настройки TypeScript
└── playwright.config.ts     # Конфигурация Playwright (разделение проектов, локали, webServer)
```

## 🧪 Реализованные тестовые сценарии

### 1. Финтех-контур: Проверка идемпотентности платежей (API)

Сценарии тестируют поведение платежного шлюза при повторных отправках транзакций, используя заголовок `idempotency-key` (UUID):

- **Первый запрос:** Создает запись в `db.json` со статусом `201 Created` и кэширует её в middleware.
- **Повторный запрос:** Перехватывается middleware, возвращает идентичный ответ из оперативной памяти без повторной записи в БД.
- **Изоляция:** Перед каждым тестом хук `beforeEach` очищает базу данных и кэш ключей через эндпоинт `/payments/clear`.

### 2. Тревел-контур: Кроссбраузерный поиск и Mocking (UI)

Сценарии тестируют интерфейс поиска отелей на сайте `Ostrovok.ru` на базе трех движков (**Chromium, Firefox, WebKit**):

- **Оптимизация трафика (Page Fixture):** Кастомный перехватчик страниц автоматически блокирует тяжелый медиа-контент (картинки), рекламные скрипты (`Flocktory`) и аналитику (`GTM`, `Метрика`). Это сократило время прогона **в 2–3 раза** и убрало проблему перекрытия элементов виджетами.
- **Подмена данных (Mock API):** С помощью `page.route()` полностью заизолирован реальный бэкенд автокомплита. Фронтенд успешно протестирован на способность корректно обрабатывать и рендерить кастомные тестовые данные из TS-фикстуры (город «Атлантида»).
- **Стабильность локали:** Браузеры принудительно инициализируются с локалью `ru-RU` и таймзоной `Europe/Moscow`, предотвращая баги переключения языков интерфейса.

## 🛠️ Системные требования и окружение

1. **ОС:** Windows 10/11 с установленной **WSL 2** (дистрибутив Ubuntu) или macOS/Linux.
2. **Node.js:** Версия `v18` или выше.
3. **IDE:** VS Code с расширениями _WSL_, _Playwright_ и _Prettier_.

## 📥 Быстрый старт (Развертывание)

Откройте ваш терминал (в случае Windows — терминал дистрибутива WSL), склонируйте проект и выполните установку:

```bash
# 1. Установите зависимости Node.js
npm ci

# 2. Установите системные библиотеки Linux и бинарники браузеров Playwright
npx playwright install --with-deps
```

## 🚀 Запуск тестов

Благодаря встроенной секции `webServer` в `playwright.config.ts`, вам **не нужно вручную запускать Express-сервер** перед API-тестами — раннер автоматически поднимет его на порту `3000` и корректно погасит после завершения сессии.

### Раздельный запуск по контурам (Рекомендуется)

```bash
# Запустить только Fintech API-тесты (в один поток для чистоты сессий памяти)
npm run test:api

# Запустить только Travel UI-тесты во всей матрице браузеров (Chromium, Firefox, WebKit)
npm run test:ui

# Запустить тесты только в конкретном окружении (например, Safari/WebKit)
npx playwright test --project=travel-ui-webkit
```

### Общий прогон и отчетность

```bash
# Запустить абсолютно все тест-сьюты во всех окружениях разом
npx playwright test

# Посмотреть интерактивный HTML-отчет с трассировкой шагов
npx playwright show-report
```

## 🔄 Непрерывная интеграция (CI/CD)

В репозиторий интегрирован автоматический пайплайн **GitHub Actions** (`.github/workflows/playwright.yml`), который:

1. Запускается на каждый `push` или `pull_request` в ветки `main`/`master`.
2. Разворачивает изолированное окружение на базе Ubuntu Linux в режиме `headless`.
3. Запускает последовательно API-контур платежей и кроссбраузерную матрицу UI-контура.
4. Сохраняет артефакты отчетов (`playwright-report/`) на 14 дней в случае падения тестов.
